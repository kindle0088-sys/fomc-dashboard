# FOMC 前瞻看板

按会议周期循环运行的**验证型**看板——不是"决议前夜截个图"，而是每场会议都留下
「事前怎么想 → 事后对不对」的可复算记录。

## 定位

| 不是 | 而是 |
|------|------|
| 一次性快照 | 循环运行的验证档案 |
| 引用别人的概率 | 每个数字都能自己复算 |
| 只展示结论 | 展示结论 + 触发条件 + 事后归因 |

## 核心产出

**一张图 + 一张表 + 一层情景**：

- **图**：利率路径——市场隐含（期货反算）／美联储 SEP 中值／三条情景路径（C1 温和 / C2 中性 / C3 激进），看分歧与漂移
- **表**：本场 vs 上场 vs 实际 的对比矩阵
- **情景层**：三轴情景 + 历史实测的资产反应矩阵（1日/10日/1月/3月/6月/1年）

## 数据源

| 来源 | 内容 | 认证 | 限制 |
|------|------|------|------|
| **CME 结算价 API** | 30 天联邦基金期货全曲线（60+ 合约） | 无需 | ⚠️ **只保留约 7 个交易日，必须每日抓** |
| **FRED CSV** | 政策利率、通胀、就业、流动性、金融条件、市场 | 无需 | 政策利率 1 天延迟 |
| **FRED DFEDTAR / DFEDTARU** | 目标区间上/下限的完整日频序列（1982 起） | 无需 | 用于**自动探测加息事件日**，免人工录入 |
| **Yahoo v8 chart API** | 长历史资产序列：标普/纳指/美元指数/黄金/VIX/高收益债 | 无需 | 必须用 `period1=0&interval=1d`；⚠️ `range=max` 会静默降频为季度 |
| Fed 官方 SEP PDF | 点阵图、经济预测 | 无需 | 需解析器 |
| CME FedWatch | 市场概率（加工后） | 无公开 API | ⚠️ 仅作交叉校验引用，**不可复算** |
| 一致预期 / 票委阵营 | 机构预测中值、鹰鸽判读 | — | 无结构化源，人工维护 |

CME 反算公式：`隐含利率 = 100 − settle`

## 目录结构

```
fomc-dashboard/
├── config/
│   ├── series.json          # FRED 序列清单 + CME 接口配置

│   ├── history-series.json  # L4 长历史序列清单 + 加息事件探测源
│   └── scenarios.json       # 三轴情景定义 + 概率 + 触发条件（人工维护）
├── scripts/
│   ├── collect.mjs          # 现状层采集（CME + FRED → raw + 快照 + 派生）
│   ├── collect-history.mjs  # 长历史采集 + 加息事件自动探测
│   ├── build-scenarios.mjs  # L4 情景层计算（事件研究 → 反应矩阵）
│   ├── build-dashboard.mjs  # 看板生成
│   └── daily.mjs            # 每日全链路 + git 提交
├── data/
│   ├── raw/                 # 最新原始数据
│   ├── snapshots/<日期>/     # 每日永久留档
│   ├── history/             # 长历史序列（不入库，可重建）
│   └── derived/             # 派生指标（current.json / scenarios.json）
├── docs/                    # 看板产物
└── run-daily.cmd            # 计划任务启动器
```

## 用法

```bash
node scripts/collect.mjs                    # 抓现状层（CME + FRED）
node scripts/collect.mjs --cme-only         # 只抓期货曲线
node scripts/collect.mjs --date 09/21/2026  # 指定 CME 结算日

node scripts/collect-history.mjs            # 长历史 + 加息事件探测（约 2.2MB，本地缓存）
node scripts/build-scenarios.mjs            # 重算 L4 情景层
node scripts/build-dashboard.mjs            # 重建看板

node scripts/daily.mjs                       # 全链路：采集 → 历史 → 情景 → 看板 → 提交
```

## L4 情景层：三轴设计

三轴共用同一套历史事件样本与同一计算口径，区别只在**事件如何分组**——它们回答三个不同层面的问题，因此可以同时成立：

| 轴 | 问题 | 分组方式 | 时间尺度 |
|----|------|---------|---------|
| **A · 加息性质** | 这是哪一种加息周期？ | 按周期性质（预防式 / 正常化 / 追赶式） | 周期级 |
| **B · 单场结果** | 这次会议会怎么走？ | 按单次加息幅度（25bp / ≥50bp） | 会议级 |
| **C · 路径终点** | 这轮最终加到哪？ | 按所属周期的累计加息幅度 | 年度级 |

**事件研究方法**：

- **事件日 t0** = 目标利率生效日，由 FRED `DFEDTAR`（1982–2008）+ `DFEDTARU`（2008–今）自动探测，**非人工录入**
- **基准** = t0 前一交易日收盘（保证基准尚未反映新政）
- **窗口** = 事件后 1d / 10d / 1M / 3M / 6M / 1Y（按交易日计：1 / 10 / 21 / 63 / 126 / 252）
- **统计量** = 组内中位数 + 四分位（中位数比均值稳健）
- **资产** = 标普500、纳斯达克、美元指数、黄金、VIX、高收益债 ETF、10Y、2Y、10Y−2Y、3M（10 个）
- **样本池** = 1994 年至今 52 次加息，其中 51 次作为历史样本

**为什么排除 1985–1989**：那一时期调整幅度为 6.25 / 12.5 / 18.75 / 43.75bp 的碎步（贴现率时代遗留），与 1994 年后的 25bp 制式不可比。

**为什么 B3「按兵不动」不入矩阵**：它没有政策生效日，无法套用统一的事件口径。

## 时区约定

决议结果于会议最后一日美东 14:00 公布 = **SGT 次日 02:00**（夏令时）／**03:00**（冬令时）。
所有落盘时间戳统一用 SGT（+08:00）。
